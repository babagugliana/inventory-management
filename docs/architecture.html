System Architecture

Factory Inventory Management System

A demo supply-chain analytics application. A Vue 3 single-page app renders six dashboards against a Python FastAPI service that filters and aggregates a fixed set of JSON fixtures held in memory. There is no database, no authentication, and no persistence — the whole system is a read-oriented pipeline from static files to charts.

Data Flow — a filtered dashboard load

User changes a filter
FilterBar.vue binds four selects with v-model to refs exported by useFilters. Because those refs live at module scope, every view shares one instance.
Views react
Each view watches [selectedPeriod, selectedLocation, selectedCategory, selectedStatus] and re-runs its loader. Dashboard.vue fires four requests in parallel via Promise.all.
Query string is built
api.js converts filters into URLSearchParams, omitting any value equal to all, then issues GET http://localhost:8001/api/… through axios.
FastAPI filters in memory
Query params arrive as Optional[str] handler arguments. apply_filters narrows by warehouse, category and status (case-insensitive); filter_by_month matches a YYYY-MM prefix or expands a quarter key such as Q3-2025 via QUARTER_MAP. Aggregate endpoints then sum, count and average over the surviving rows.
Pydantic validates the response
Endpoints declared with response_model coerce and validate each record before it is serialised. A JSON field that stops matching its model surfaces here as a server-side error.
Raw data lands in refs
Views store responses in refs such as allOrders and inventoryItems, and never mutate them afterwards.
Computed properties derive the view
Everything on screen — status breakdowns, category totals, order trends, top products, SVG chart geometry — is a computed over those refs, so the DOM updates once and only where the derived values changed.

Inventory has no time dimension, so the period filter is deliberately not forwarded to /api/inventory. Currency is a pure display concern: amounts stay in USD end-to-end and utils/currency.js converts to JPY at a fixed rate of 150 only at render time.

Test coverage

Three pytest modules exercise the API through FastAPI's TestClient, importing main.app directly — no server process required. They cover dashboard aggregation, inventory filtering and the remaining endpoints. The Vue layer has no automated tests.

Implementation Notes

Worth knowing before you change anything

  • The client calls endpoints the server does not implement. api.js defines getTasks, createTask, deleteTask, toggleTask, createPurchaseOrder and getPurchaseOrderByBacklogItem against /api/tasks and /api/purchase-orders, but main.py has no such routes. Those requests 404; the callers catch and log the failure, so the UI silently falls back to the mock tasks held in useAuth. The PurchaseOrder and CreatePurchaseOrderRequest Pydantic models exist but are unused — the backend half of the feature was never written.
  • No persistence layer. Fixtures load once at import. Any write path added later needs both a storage decision and a reload strategy.
  • CORS is wide open (allow_origins=["*"]) and there is no authentication or rate limiting. Acceptable for a local demo, not for deployment.
  • The API base URL is hard-coded to http://localhost:8001/api in api.js, so the frontend only works against a local backend.
  • Quarter handling is duplicated. QUARTER_MAP drives filter_by_month, while /api/reports/quarterly re-derives quarters with its own if-else chain. Changing the fiscal calendar means editing both.
  • Dashboard.vue is 1,271 lines and Spending.vue 852 — the two places where extracting components would pay off first.
